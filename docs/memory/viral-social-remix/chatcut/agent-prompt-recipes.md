# ChatCut Agent 提示词配方

这些提示词用于 AI Panel 的 `Agent` 模式。尽量用 `Selection` 选择具体素材、
时间点、Transcript 文字或预览区域，让输入框出现 `@` 引用，再发送请求。

提示词不应把未知项目事实写死。尖括号字段必须替换，不能原样发送。

## 1. 只分析，不修改

```text
先不要修改项目。请检查我引用的素材、当前 Timeline、画幅、fps、总时长和可用
Transcript。列出按时间顺序真实出现的动作/台词、最强 Hook 候选、重复或无信息
片段、音频问题和素材缺口。

然后从“感官食欲、懒人省时、教程、Talking Head、科普、UGC 商品安利、
App Promo、测评对比、Before/After、清单、高级品牌、Vlog、故事、悬念、
节日、幕后”中选一个主主题和最多一个辅助主题。说明选择证据，并给出
Hook、Context、Mechanism、Proof、Result、CTA/Exit 的 beat sheet。
不要编造画面、台词、价格、功效或促销。
```

适用：素材复杂、用户只给了方向、准备大改前。

## 2. 干净导入与结构粗剪

```text
把我引用的素材作为独立可编辑项目放到主视频轨，按 <顺序规则> 排列，从第 0 帧
开始，不留意外空隙。先只做选段、排序和裁切，保留动作完成与语义完整。

这一步不要添加字幕、标题、logo、BGM、音效、转场、滤镜或 Motion Graphics。
完成后重新检查主视频轨，报告每个项目的开始帧、结束帧、时长和总时长。
```

适用：先建立可逆底稿，尤其是多个生成片段。

## 3. Talking Head 紧凑剪辑

```text
对我引用的 Talking Head 素材先在 Transcript 中识别最强观点、必要前提、理由、
例子和结论。删除寒暄、重复、无意义口头语和不影响含义的停顿，但保留必要呼吸、
限定词和自然语气，不改变说话者立场。

把最强且能独立理解的观点放在开头。每 4-8 秒只在有意义时加入一种视觉变化：
相关 B-roll、构图变化、短关键词或例子。不要给每个词做弹跳强调。
保持原始对白为声音主角，BGM 只能轻铺。完成后检查每个 Transcript 切点前后
句意、画面跳切、环境声连续性和字幕准确性。
```

## 4. 无对白食物 B-roll

```text
这是一条无对白 <菜品/商品> 竖屏短片。不要生成假 Transcript 或假台词。
以 <感官食欲 / 懒人省时 / 教程> 为主主题，把可见动作整理成：
Hook、准备、关键变化、成品、干净结尾。

先在动作接触点、倒入点、翻炒点、切开点、抬起点做切分。主画面保留在 V1。
如需步骤文字，在上层使用同一个可复用 Motion Graphic，逐实例替换 2-5 个词的
英文标签；文字必须描述当前画面。BGM 放独立音轨并对齐全片；只在能看到对应动作
时加入 pouring、sizzling、chopping、plating 等 Foley。

最后检查最长标签、字幕安全区、食物是否被遮挡、Foley 同步、BGM 结尾和总时长。
```

## 5. UGC 商品广告

```text
把我引用的素材剪成 <目标时长> 的 UGC 风商品短片，主主题是“真实问题被解决”。
结构为：具体痛点、真实使用、一个核心机制、可见证明、适用人群/限制、CTA。

优先保留自然使用、手部操作和真实反应。商品名称第一次出现要清楚，但不要持续
霸屏。所有卖点、价格、折扣、功效、评分和限时信息只能使用我提供或素材中可验证
的事实；缺失就省略。CTA 必须放在 Proof 后。

先完成结构和节奏，再加短文字与声音。不要把成片剪成纯棚拍，不要让 logo 先于
观众价值。完成后列出每个卖点对应的证据镜头。
```

## 6. App / 网站功能演示

```text
把我引用的录屏剪成 <目标时长> 的 <9:16/16:9> App Promo。结构为：
用户问题、进入产品的最短路径、一次完整关键操作、明确结果、下一步。

每次点击前要让观众看清目标控件，点击后保留到结果稳定出现。放大只用于当前操作，
不要让光标瞬移，不要补造不存在的界面或功能。文字只使用简短动作词，例如 Search、
Compare、Save、Order。UI 自身变化是主要运动，不要用转场抢注意力。
```

## 7. 同一素材做多主题版本

```text
保留当前 Timeline 不覆盖。为同一组素材建立两个独立版本：

版本 A：<主题 A>，目标是 <目标 A>，时长 <时长 A>。
版本 B：<主题 B>，目标是 <目标 B>，时长 <时长 B>。

两个版本都必须使用素材真实证据，但 Hook、节奏、文字密度、声音和结尾应体现主题
差异。不要只是换字体或 BGM。完成后用表格比较两版的第一镜、平均节奏、Proof、
CTA 和适用平台。
```

适用：让低级模型真正理解主题不是皮肤。优先用多个 timelines/sequences 保存。

## 8. 统一 Motion Graphic 标签

```text
为我引用的步骤/标签创建一个可复用 Motion Graphic 模板，再在上层轨道按 beat
放置多个实例，只覆盖每个实例的文字。样式要求：<字体、颜色、位置、阴影/描边>。

先用全片最长的一条文字测试边界，再应用其他文字。标签不能遮住主体，必须位于
<平台> 的安全区域。不要为每条标签生成不同资产。完成后检查开头、中段、最长标签
和结尾代表帧。
```

## 9. 音频 finishing

```text
先识别当前视频是否有对白、环境声或完全无音轨。对白存在时以对白清晰为最高优先级；
无对白时以画面节奏决定 BGM。

把原始对白/主声音、BGM、Foley 分层放置。BGM 从开头到视频结尾，不留长尾，并在
有对白时主动让位。Foley 只对应可见动作，不为每个切点加声音。检查开头、中段、
最响动作、CTA 和最后 2 秒，报告是否有爆音、突然静音、错位或尾巴。
```

## 10. 只验收，不再创作

```text
不要新增创意或重做风格，只做验收。检查当前项目：

1. 画幅、fps、总时长和导出范围；
2. 每条轨道的职责、意外空隙、重叠和多余项目；
3. Hook、主体 Proof、Result 和结尾是否完整；
4. 字幕准确性、最长文字、边界和安全区；
5. 对白可听性、BGM/Foley 同步及结尾；
6. 开头、中段、关键切点和结尾代表帧。

用“通过 / 失败 / 无法确认”逐项报告。对失败项给最小修复方案；无法确认的项不要
假设通过。
```

## 保存为 Skills 的规则

ChatCut 的 `Skills` 选择器可以保存当前编辑流程。保存前必须去掉：

- 当前项目的素材 ID、项目 ID、时间线 ID 和绝对文件路径。
- 某次视频专属的菜名、人物名、台词和品牌结论。
- 授权信息、导入令牌、生成确认状态和签名链接。

保留可复用部分：

- 观察顺序；
- 主题选择条件；
- beat sheet；
- 轨道职责；
- Pass 顺序；
- 验收清单；
- 需要由用户填入的变量。

好的 Skill 是一个决策流程，不是某次成片的复制记录。
