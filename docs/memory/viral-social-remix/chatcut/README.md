# ChatCut 剪辑记忆

这组笔记把 ChatCut 的产品事实、剪辑判断和低级模型执行规则分开保存。
目标不是让模型“知道几个按钮”，而是让它能从内容目的推导出节奏、镜头、
文字、动效、声音、品牌露出和验收方法。

## 阅读顺序

执行 ChatCut 剪辑任务时，按下面顺序加载：

1. [[editor-capability-map]]：确认编辑器实际具备什么，不虚构功能。
2. [[low-model-editing-contract]]：按固定流程观察、决策、执行和验收。
3. [[theme-playbooks]]：选择一个主主题和最多一个辅助主题。
4. [[agent-prompt-recipes]]：把意图写成 ChatCut Agent 能理解的具体请求。
5. [[chatcut-handoff-workflow]]：视频生成后的导入、时间线、导出和已有事故经验。

## 三层知识不能混用

### 产品事实

只写 ChatCut 已确认存在的界面、面板、操作和导出能力。事实来源见
[[editor-capability-map]]。

### 剪辑策略

包括“什么时候快切”“何时留白”“品牌何时出现”“字幕该多长”等。这些是
可调整的默认判断，不是 ChatCut 的硬限制。

### 单次项目事实

素材中实际出现的动作、台词、人物、商品和时长，必须从当前项目观察得到。
不能因为某个旧案例用过 `Soy Sauce`，就给新视频也编出同样的字幕。

## 给低级模型的最高优先级规则

- 先观察素材，再做主题判断；不要只看文件名或用户的一句话就开始装饰。
- 一个视频只选一个主主题，最多加一个辅助主题。主题不是滤镜，而是
  “观众承诺 + 情绪 + 节奏 + 证据”的组合。
- 先完成故事结构和干净切点，再加字幕、动效、音乐和音效。
- 原始画面优先保留在 `V1`；附加画面、字幕/动效和声音分层放置，保持可编辑。
- 对白视频优先保证语义和可听性；无对白 B-roll 不要伪造 Transcript 或台词。
- 文字只描述画面或真实台词。没有证据的价格、时长、功效和排名不能写。
- 每个转场、动效、音效必须承担一个任务：说明、强调、隐藏切点或制造节奏。
  如果说不出任务，就删掉。
- 生成类操作可能需要额度确认；不能把未获确认的生成任务当作已经完成。
- “时间线看起来正确”不等于成片正确。要检查代表帧，并验证最终导出文件。
- 不保存授权码、导入令牌、签名媒体链接、原始供应商响应或任何密钥。

## 建议的时间线分层

这是仓库的推荐约定，不是 ChatCut 的强制轨道名称：

| 轨道 | 推荐用途 |
| --- | --- |
| `V1` | 主叙事、A-roll、主要料理过程或产品演示 |
| `V2` | B-roll、补画面、反应镜头、局部放大 |
| `V3` | 字幕、标签、Motion Graphics、CTA |
| `A1` | 原始对白或主叙述 |
| `A2` | BGM |
| `A3` | Foley、环境声和强调音效 |

先让每一层职责单一，低级模型才容易发现错轨、错时长、遮挡和音频尾巴。

## 完成定义

一次剪辑只有同时满足以下条件才算完成：

- 内容目标和主主题明确。
- 开头、主体、证明、结果和结尾各自承担清晰作用。
- 时间线没有意外空隙、重叠或多余素材。
- 字幕可读、与画面/台词一致，并位于安全区域。
- BGM、对白和音效没有互相争抢；所有声音与视频同时结束。
- 项目画幅、帧率、导出范围和平台用途一致。
- 代表帧通过视觉检查；导出文件的分辨率、时长、帧率和音轨通过检查。
