# 低级模型剪辑执行契约

低级模型容易直接套模板、乱加效果、编造字幕，或只检查时间线 JSON 而不看成片。
本契约把剪辑拆成不可跳过的决策门，适用于 ChatCut Agent 或其他执行模型。

## 第一原则：先做内容判断，再做软件操作

剪辑主题不是字体、滤镜或转场。主题由四部分组成：

```text
主题 = 观众承诺 + 主情绪 + 节奏规则 + 证据形式
```

例如“15 分钟懒人晚餐”：

- 观众承诺：快、少洗锅、能做出来。
- 主情绪：轻松、有用、食欲。
- 节奏规则：前快后稳，省略重复动作。
- 证据形式：一锅完成、关键步骤、最终成品。

只换成暖色滤镜不叫学会这个主题。

## 不可跳过的七步

### 1. 观察

先读取项目和素材，再填写事实表：

| 字段 | 必填内容 |
| --- | --- |
| 平台/画幅 | 例如 Reels，`9:16` |
| 目标时长 | 用户要求或现有素材可支持的时长 |
| 主体 | 人、菜品、App、商品或事件 |
| 真实动作 | 按出现顺序列出，不推测 |
| 真实台词 | 有就摘要；没有就写“无对白” |
| 最强证据 | 最诱人的成品、最清楚的演示、最有力的观点或结果 |
| 不可改项 | 品牌、商品外观、关键句、法务要求、原始音频等 |
| 素材风险 | 模糊、跳帧、口误、重复、比例混杂、音频缺失等 |

看不到的内容写“未知”，不能补想象。

### 2. 定义任务

只写一个主目标：

- 留住观众；
- 讲清步骤；
- 建立可信度；
- 证明效果；
- 推动点击/购买；
- 保留氛围；
- 压缩长讲话；
- 做平台适配。

多个目标冲突时，用户目标优先；没有明确优先级时，保留内容正确性和可理解性，
再追求更强节奏。

### 3. 选择主题

从 [[theme-playbooks]] 选择：

- 一个 `primary_theme`；
- 零个或一个 `secondary_theme`；
- 一句解释为什么素材支持它。

如果素材不能提供主题需要的证据，不选该主题。例如没有前后对比画面，就不能
硬做 `Before / After`。

### 4. 写 Beat Sheet

先写节拍，再动时间线：

| Beat | 时间范围 | 画面事实 | 叙事作用 | 文字 | 声音 |
| --- | --- | --- | --- | --- | --- |
| Hook |  |  | 为什么继续看 |  |  |
| Context |  |  | 观众需要知道什么 |  |  |
| Mechanism |  |  | 过程/原因/演示 |  |  |
| Proof |  |  | 可信证据 |  |  |
| Result |  |  | 满足感或结论 |  |  |
| CTA/Exit |  |  | 下一步或干净收尾 |  |  |

不是每条片都要六段齐全，但 Hook、主体证明和清楚结尾不能同时缺失。

### 5. 分 Pass 执行

严格按顺序：

1. `Structure pass`：选段、排序、裁切、去重复、确定开头和结尾。
2. `Continuity pass`：检查动作接续、视线、空间方向、对白语义和呼吸。
3. `Rhythm pass`：根据主题调整镜头长短，在动作点或语义点切。
4. `Text pass`：只加入必要字幕、步骤标签、数据或 CTA。
5. `Motion pass`：只用来强调、解释、隐藏合理切点或建立节奏。
6. `Audio pass`：对白、BGM、环境声和 Foley 分层，保证结尾对齐。
7. `Brand pass`：确认品牌/商品出现自然、清楚且没有错误变形。

前一 Pass 不通过，不进入后一 Pass。不要用动效掩盖结构问题。

### 6. 验证

至少检查：

- 时间线开头、中段、结尾和每个关键切点。
- 最长字幕、最靠近画面边缘的字幕和 CTA。
- BGM 是否压住对白；音效是否与可见动作同步。
- V1 主叙事是否被附加层意外遮挡。
- 总时长、空隙、重叠和末尾声音尾巴。
- 导出范围是否为 Full timeline 或正确的 Zone。

帧率不一致时，不要直接把“源文件帧数”当成 ChatCut 时间线帧数：

```text
真实时长秒数 = 源文件帧数 / 源文件 fps
时间线帧数 = round(真实时长秒数 × 项目 fps)
```

最终以导出文件的实际时长为准。仓库已有 24fps 源素材进入 30fps 时间线后被错误
导成 12 秒的事故，见 [[chatcut-handoff-workflow]]。

### 7. 报告

完成报告必须包含：

- 做了什么，以及没有做什么。
- 主主题和关键节拍。
- 时间线/序列、画幅、fps 和总时长。
- 轨道职责和新增元素。
- 已检查的代表帧与导出文件属性。
- 仍然存在的限制或需要人工判断的地方。

不能只说“完成了”。

## 低级模型的停止条件

遇到下列情况不要擅自继续：

- 用户要求的品牌、价格、功效或法律表述没有可靠来源。
- 素材缺失到无法支撑核心故事。
- 需要生成 Motion Graphics、Video 或 Image，但额度确认被拒绝、取消或超时。
- 用户要求“保留原话”，但 Transcript/音频无法读取。
- 画幅、目标平台和交付版本存在会改变剪辑结构的冲突。

一般的审美选择不属于停止条件。根据主目标做保守、可逆的默认判断即可。

## 反套路规则

- 不要每 0.5 秒切一次；快节奏不等于无意义抖动。
- 不要给每个切点加转场；动作本身通常就是最好的转场。
- 不要给每个词做弹跳字幕；只强调真正改变理解的词。
- 不要用“电影感”代替具体说明；写清楚光线、镜头距离、节奏和声音。
- 不要在开头先放 logo，再给观众理由；先给价值或感官证据。
- 不要在无对白片里制造假台词。
- 不要把参考片的文字和音乐原样搬到新片；只抽取节奏和结构规律。
- 不要让 BGM 比故事更像主角。
- 不要让 CTA 突然中断情绪；它应由前面的证据自然推出。

## 标准输出格式

执行模型在动手前应先内部完成以下结构；需要用户审阅时可直接展示：

```yaml
edit_plan:
  objective: ""
  platform: ""
  aspect_ratio: ""
  project_fps: 30
  target_duration_seconds: 0
  primary_theme: ""
  secondary_theme: null
  theme_reason: ""
  source_facts:
    subject: ""
    dialogue: ""
    strongest_proof: ""
    must_keep: []
    risks: []
  beats:
    - role: hook
      time: ""
      visual: ""
      purpose: ""
      text: ""
      audio: ""
  tracks:
    V1: ""
    V2: ""
    V3: ""
    A1: ""
    A2: ""
    A3: ""
  qa:
    representative_frames: []
    text_checks: []
    audio_checks: []
    export_checks: []
```

## 可复制的总控提示词

```text
你是 ChatCut 剪辑执行模型。先观察当前项目、My Assets、Timeline 和可用
Transcript，不要凭文件名编造内容。先确定一个主目标、一个主主题和最多一个
辅助主题，再写 Hook、Context、Mechanism、Proof、Result、CTA/Exit 的节拍。

按 Structure、Continuity、Rhythm、Text、Motion、Audio、Brand 七个 pass
执行。先解决选段和切点，再加字幕、动效和声音。每个效果必须承担说明、强调、
隐藏合理切点或制造节奏中的一个任务，否则不添加。

默认保持主画面在 V1，补画面在 V2，字幕/动效在 V3，原始对白在 A1，BGM 在
A2，Foley/强调音效在 A3。无对白素材不要编造 Transcript 或台词。所有字幕、
价格、功效、步骤和品牌信息必须来自可见画面、真实台词或用户提供的事实。

修改后检查开头、中段、结尾、所有关键切点、最长字幕、字幕安全区、对白可听性、
BGM 结尾、空隙、重叠和总时长。若项目 fps 与源素材 fps 不同，按真实秒数换算
时间线帧数。最后报告时间线、轨道、时长、已验证内容和仍有限制，不能只说完成。
```
